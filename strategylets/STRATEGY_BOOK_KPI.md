# 策略书 KPI 与准入标准

## 目的

leader 提的问题已经不是“这个策略有没有想法”，而是“做到什么程度，才算够格进入策略集，而且是进入哪个池子”。  
这份文档把门禁从单品种升级成统一口径，避免后面批量做策略时再大批量返工。

## 总原则

- `通用策略集` 默认评估宇宙固定为 `BTCUSDT 5m + ETHUSDT 5m`。
- 同一策略、同一参数、同一时间窗下，必须同时评估 `BTC`、`ETH` 和 `BTC+ETH 合并结果`。
- `BTC`、`ETH` 单品种都不能掉到硬失败区。
- `BTC+ETH` 合并结果必须达到正式通过线，才有资格进入通用策略集人工复核。
- 只在单一品种稳定有效的策略，不进入通用策略集，单列到 `品种特化策略池`。

## 两层门禁

### 第一层：单品种底线

每个标准策略运行后，都会先生成单品种评估，默认至少包含：

- `BTCUSDT`
- `ETHUSDT`

单品种使用以下自动 KPI：

1. `无过滤机会频率`
   - 定义：`signal_count / sample_days`
   - 口径：先用 `signal_count` 近似 `unfilter` 机会数
   - 正式通过线：`>= 0.75 次/天`
   - 观察线：`>= 0.10 次/天`
   - 说明：这是一次“中度放宽”，目标是减少对中低频策略的早筛误杀，不代表通用策略集整体放松质量要求

2. `基线表现`
   - 正式通过线：`avg_r >= 0` 且 `profit_factor >= 1.0` 且 `max_drawdown >= -0.25`
   - 观察线：`avg_r >= -0.05` 且 `profit_factor >= 0.95` 且 `max_drawdown >= -0.35`

3. `样本充足性`
   - 正式通过线：baseline 交易 `>= 100` 笔
   - 观察线：baseline 交易 `>= 40` 笔
   - 说明：这次只放宽频率与样本，不调整基线表现

4. `实盘化前提`
   - 必须 `realtime_safe = true`
   - 必须 `uses_future_bars = false`
   - 必须 `supports_visualization = true`
   - 如果策略用指标做机会判断或强弱判断，这些指标必须能画在主图或副图，让人直接看到决策依据

单品种自动结论分三档：

- `通过`
- `观察`
- `不通过`

进入通用策略集的底线要求不是“BTC 和 ETH 都正式通过”，而是：

- `BTC >= 观察`
- `ETH >= 观察`

也就是说，两个品种都不能掉到硬失败区。

### 第二层：BTC + ETH 合并门禁

在 `BTC`、`ETH` 单品种都不失败的前提下，再对两者合并结果重算一套 KPI。

这里不能直接平均单品种摘要值，必须从合并后的原始结果重算：

- 机会频率：基于合并信号数和重叠样本时间窗
- 基线表现：基于合并 `trade ledger / equity curve`
- 样本充足性：基于合并交易数

合并结果仍使用同一套数值线，但这里要求的是正式通过线：

- 机会频率：`>= 0.75 次/天`
- 基线表现：`avg_r >= 0` 且 `profit_factor >= 1.0` 且 `max_drawdown >= -0.25`
- 样本充足性：`>= 100` 笔 baseline 交易
- 实盘化前提：必须继续满足

如果 `BTC`、`ETH` 都不差，但合并结果只有观察级，则先放 `观察名单`，不进入通用策略集。

## 人工图表复核

只有当自动门禁满足以下条件时，才进入人工复核：

- `BTC >= 观察`
- `ETH >= 观察`
- `BTC+ETH 合并 = 通过`

人工复核不再按单品种各抽一轮，而是使用合并抽样：

- `Top20`
- `Random20`

但必须满足覆盖下限：

- `BTC` 至少 `10` 张
- `ETH` 至少 `10` 张

如果某一品种抽样覆盖不足：

- 人工状态记为 `待补样复核`
- 不能直接判通过

人工通过线保持不变：

- `>= 70%` 的样本被判定为“结构合理、可解释、像真人会做”
- 明显误触发 / 明显未来函数嫌疑样本 `<= 3` 张

人工复核结论分四档：

- `通过`
- `待人工复核`
- `待补样复核`
- `不通过`

## 最终归类

### 1. 可纳入通用策略集

同时满足：

- `BTC >= 观察`
- `ETH >= 观察`
- `BTC+ETH 合并 = 通过`
- 人工复核 `通过`

### 2. 待人工复核

同时满足：

- `BTC >= 观察`
- `ETH >= 观察`
- `BTC+ETH 合并 = 通过`
- 但人工复核还没完成，或抽样还不足

### 3. 观察名单

同时满足：

- `BTC >= 观察`
- `ETH >= 观察`
- `BTC+ETH 合并 = 观察`

### 4. 品种特化策略池

不满足通用门禁，但满足：

- `BTC` 或 `ETH` 中至少一个品种达到单品种正式通过线
- 且人工复核 `通过`
- 需要显式记录 `applicable_symbols`

### 5. 暂不纳入

满足任一情况：

- `BTC` 或 `ETH` 中有品种跌到观察线以下
- 实盘化前提失败
- 人工复核明确 `不通过`

## 当前落地方式

标准策略默认通过批量入口运行：

```powershell
.venv\Scripts\python.exe .\scripts\run_strategylet_batch.py --spec <spec_id>
```

默认行为：

- 自动查找 `BTCUSDT 5m` 与 `ETHUSDT 5m` 历史文件
- 先分别跑单品种子目录
- 再在同一个 `run_id` 下生成合并版：
  - `strategy-book-assessment.json`
  - `backtest-summary.json`
  - `quant_run.json`
  - `README.md`

输出目录结构示意：

```text
产出/标准策略/<spec_id>/<run_id>/
  strategy-book-assessment.json
  backtest-summary.json
  quant_run.json
  README.md
  symbols/
    BTCUSDT/
    ETHUSDT/
```

## 为什么这样拆

- `单品种底线` 解决“某个策略是否在某个品种上已经明显不成立”
- `合并门禁` 解决“它能不能作为通用策略集的一员，而不是只在某一边看起来还行”
- `人工图表复核` 解决“量化规则虽能触发，但图上是否真的像真人会做”
- `品种特化策略池` 解决“不要把明显只适合特定市场的策略硬塞进通用池”
- `频率 / 样本中度放宽` 主要解决研究入口问题，让值得继续看的策略更容易进入观察名单，而不是直接证明策略可入通用池
